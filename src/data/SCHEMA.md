# Схема JSON дерева решений

Файл юнита: `{ "id": "...", "name": "...", "tree": <Node> }`

Исключение — `shooter.json`: у Стрелка два разных скрипта в зависимости
от глобальной цели ИИ, поэтому вместо `tree` у него
`"trees": { "keyPoints": <Node>, "suppression": <Node> }`.

## Глобальная настройка "цель ИИ"

`aiGoal` (`"keyPoints" | "suppression"`) выбирается один раз перед
партией (экран настроек, хранится в localStorage) и не меняется по
ходу сценария. Влияет на:

- какой `trees.<goal>` использовать для Стрелка;
- какую памятку показывать вместо специального ключа `"targetSelection"`
  в `memo` (маппится на `targetSelection_keyPoints` или
  `targetSelection_suppression` из `common.json` в зависимости от
  текущего `aiGoal`).

Памятки с фиксированным приоритетом, не зависящим от `aiGoal`
(например `targetSelection_sniper`, `mortarSquareSelection`), указываются
в `memo` напрямую по своему ключу.

## Типы узлов (Node)

- `question` — да/нет. Поля: `text`, `yes` (Node), `no` (Node), опционально `memo` (ключ из `common.json`.memos, показывается вместе с вопросом) и `note` (короткая ремарка под вопросом).
- `choice` — выбор одного из нескольких вариантов. Поля: `text`, `options` (массив `{ "label": "...", "next": Node }`), опционально `memo`, `note`.
- `action` — конечный узел, само действие, которое нужно выполнить. Поля: `text`, опционально `memo`, `note`.

`memo` — ссылка на пояснительный текст (памятку) из `common.json` → `memos.<key>`, показывается рядом с вопросом/действием как справка (таблица приоритетов, формула ценности точки и т.п.), сама по себе не является отдельным шагом дерева.

`note` — короткая ремарка/уточнение к текущему узлу (не требует ответа, просто контекст из правил).

## Пример

```json
{
  "id": "sniper",
  "name": "Снайпер",
  "tree": {
    "type": "question",
    "text": "Может ли снайпер атаковать?",
    "memo": "targetSelection_sniper",
    "yes": { "type": "action", "text": "Атаковать" },
    "no": { "type": "action", "text": "Приблизиться к цели" }
  }
}
```
