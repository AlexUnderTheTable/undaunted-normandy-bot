# PLAN — Undaunted Normandy веб-бот

## Цель и контекст

Пользователь играет в Undaunted: Normandy соло — сам за одну сторону,
вторая сторона разыгрывается по правилам простого соло-бота (см.
`bot_script.txt`). Бот — это не сценарий партии, а **дерево решений**:
для каждого типа юнита (стрелок, разведчик, пулемётчик, снайпер,
миномёт, командиры) есть приоритетный список действий и правила выбора
цели. Веб-приложение должно проводить игрока по этому дереву во время
игры: он выбирает юнита, чья карта выпала, отвечает на вопросы
да/нет/выбор ("может захватить?", "какая цель приоритетнее?"), а
приложение говорит, что делать.

## Решения по развилкам

- 2026-09-04: стек — Vite + React + TypeScript, без бэкенда (чистый
  фронтенд, статический деплой).
- 2026-09-04: git пока не инициализирован по решению пользователя —
  вернуться к вопросу позже.
- 2026-09-04: глубина модели — **только вопросы**. Бот не хранит
  состояние стола (юнитов, координаты, защиту) и не считает расстояния
  сам. Он задаёт вопросы ("может юнит захватить точку?" да/нет,
  "какая защита у целей?" и т.п.), а игрок отвечает по факту на столе.
- 2026-09-04: карта, которая разыгрывается на шаге раунда, выбирается
  игроком вручную из списка юнитов (карта тянется физически на столе,
  инициатива/порядок разыгрывания бот не автоматизирует в v1).

## Что подтверждено

- Источник правил — `bot_script.txt` в корне проекта (полный текст
  правил соло-бота v1.0, разделы 1-14).
- Правила состоят из: общего алгоритма "первое доступное действие
  сверху вниз по скрипту юнита" + общих правил выбора цели (3 уровня
  приоритета + исключение "разница защиты ≥2") + отдельного скрипта
  действий на каждый тип юнита + отдельных мини-скриптов для командиров
  (сержант/зам.командира/командир).

## Что ещё гипотеза

- Точная структура JSON узла дерева решений (question/choice/action,
  переиспользуемые под-деревья для выбора цели) — черновой вариант ниже,
  нужно проверить на реальном юните (Стрелок) вместе с пользователем.
- UI-паттерн: возможно повторно используемый компонент
  "вопрос → да/нет/варианты → следующий узел", плюс кнопка "назад" для
  ошибок ввода.

## Структура правил из bot_script.txt (для конвертации в JSON)

- Общие правила (не привязаны к юниту):
  - Главное правило ИИ: первое доступное действие сверху вниз (§3)
  - Выбор цели, 3 уровня приоритета + список приоритетов по 2 сценариям
    цели ("Ключевые точки" / "Подавление") (§4)
  - Исключение по разнице защиты ≥2 (§5)
  - Формула ценности ключевой точки: ПО − расстояние, штрафы за контроль
    игроком (§6, "Как выбрать ключевую точку")
  - Правило §13: если у карты юнита нет нужного действия — пропустить
    шаг скрипта, но не пропускать саму карту целиком
  - Правило §14: пополнение — только если нет более важного действия
- Юниты со своим скриптом действий:
  - Стрелок — 2 варианта скрипта в зависимости от общей цели ИИ
    (Ключевые точки §6 / Подавление §7)
  - Разведчик (§8)
  - Пулемётчик (§9, с таблицей защита→действие)
  - Снайпер (§10, приоритет цели: офицер → пулемётчик/миномёт → стрелок
    → разведчик)
  - Миномёт (§11, обстрел квадратов, выбор квадрата)
  - Сержант / Заместитель командира / Командир (§12, отдельные
    мини-скрипты воодушевления/пополнения)
